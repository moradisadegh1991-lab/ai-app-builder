# ممیزی و وضعیت اسپرینت Visual Studio

پایه `main` در commit `4f85787`؛ خط پایه: ۱۸۶ تست و typecheck موفق، بدون API پولی. مرجع مقایسه [وب‌سایت رسمی اپتو](https://appeto.ir/) تجربه انتخاب قالب، رنگ و صفحه، و ساخت و تست پیش از خرید را معرفی می‌کند. این ممیزی به معنای تأیید مستقلی از عملکرد آن سرویس نیست.

## معماری موجود

- Workspace در `src/components/ProjectWorkspace.tsx` و `workspace/`؛ Preview موجود سایت منتشرشده را در iframe sandbox نشان می‌دهد و حفظ شده است.
- تولید نیازمندی و کد در `src/lib/agents/orchestrator.ts` با checkpointهای `src/lib/workflows/queue.ts`، اجاره worker و verifier انجام می‌شود؛ مراحل موفق replay می‌شوند.
- `src/lib/ai/index.ts` و `providers.ts` مسیر مشترک همه تماس‌های AI هستند. طرح‌ها و پرداخت موجود در `billing/` است. Build و GitHub در `src/lib/pipeline.ts` و `templates/` باقی مانده‌اند.
- Migrationهای مبنا 0000 تا 0007 بودند. تغییرات 0008 تا 0010 از شاخه قبلی با حفظ journal و all-in-one منتقل شدند. هیچ Migration روی Production اجرا نشده است.

## وضعیت پیاده‌سازی

کنترل تومانی مرحله‌ای موجود در شاخه قبلی منتقل شد: رزرو اتمیک مرکزی با محدودیت مدل و نرخ تأییدشده، سقف پلتفرم/کاربر/پروژه/اجرا، نگهداری رزرو در timeout، محدودیت تعداد ساخت رایگان و ثبت برآورد مصرف. نرخ‌های ناشناخته و تنظیم ناقص مانع تماس مرکزی می‌شوند. SDK Anthropic دیگر retry پنهان ندارد. جمع هزینه پروژه فقط تخمینی است و مصرف نامعلوم را جدا نشان می‌دهد. نسخه شخصی API همچنان استفاده‌پذیر است.

**هنوز آماده فروش یا انتشار نیست:** نرخ معتبر به ازای همه مدل‌ها، دسته‌های اضافی و هزینه دقیق صورتحساب، تطبیق تاریخچه نامعلوم، مهاجرت عملی روی داده مشابه Production، پیش‌بینی پیش از اجرا به تومان و هشدار موجودی تست‌نشده/تکمیل‌نشده‌اند. رزرو مبتنی بر تخمین توکن و سربار است و تضمین مطلق صورتحساب خارجی نیست. مصرف نامعلوم تاریخی ۳۰ روزه مانع کلید مرکزی می‌شود. عدم تنظیم حدود، ساخت موبایل رایگان را متوقف می‌کند؛ به کاربران قبل از تغییر سیاست باید اطلاع داده شود. خریدهای قبلی نباید تغییر کنند.

قرارداد نسخه‌دار، داده‌محور و Canvas مبتنی بر React در `src/lib/visual/schema.ts` و `src/components/workspace/VisualCanvas.tsx` وجود دارد و متن خام به‌عنوان HTML اجرا نمی‌شود. این‌ها هنوز به پروژه، API، ذخیره‌سازی و تولید خروجی متصل نیستند؛ preview منتشرشده قبلی تغییر نکرده است. شناسه تصویر هنوز resolver مالکیت ندارد و Canvas به‌جای بارگذاری تصویر placeholder نشان می‌دهد. این مرحله Visual Editor یا Definition of Done را برآورده نمی‌کند.

## برنامه و Staging

1. سقف‌ها و تعرفه‌های معتبر مدیر را تعیین و تاریخچه مصرف را با صورتحساب آشتی دهید. نرخ نامعلوم صفر نیست. قبل از انتشار، مدل‌های مستقیم، تصویر، وضعیت timeout و تجربه کاربران پولی/رایگان بررسی شوند.
2. یک پایگاه PostgreSQL جداگانه با داده غیرحساس یا شاخه آزمایشی Neon آماده کنید. نسخه پشتیبان، Migrationهای 0008–0010 و تطبیق journal را در آن تست کنید. محدودیت شاخه Neon قبلاً مانع ساخت شاخه شد؛ هیچ شاخه‌ای حذف نشده است. `npm run db:migrate` فقط روی اتصال مستقیم پایگاه آزمایشی و با env ایزوله انجام شود.
3. API و جدول نسخه‌دار برای ذخیره مالکانه با compare-and-swap روی revision، تست درخواست هم‌زمان و reload؛ پس از آن Pages/Properties/Undo و انتخاب قالب‌ها.
4. رندر قطعی با همان schema و مسیر تحویل از قالب‌های موجود، همراه حفاظت فایل‌ها و حفظ خروجی قبلی. هر Build باید فقط به درخواست کاربر باشد.
5. تست مرورگر، پرداخت sandbox و کل جریان بدون API پولی. داده‌ای را به Production مهاجرت نکنید؛ merge/deploy فقط پس از تأیید مالک.

جزئیات بازگشت 0008–0010 و ریسک حذف اطلاعات در `docs/90-day-readiness-audit.md` ثبت شده است. کلید، توکن و داده واقعی را در logs یا repository وارد نکنید. برای مدل اقتصادی رایگان پیشنهاد اولیه: تحلیل محدود و پیش‌نمایش قالب بدون AI؛ تولید کد و APK سهمیه‌دار. این پیشنهاد هنوز سیاست فروش یا تغییر خودکار اشتراک‌های خریداری‌شده نیست.

## ادامه: پیش‌نویس ویرایشگر و خروجی فایل

شاخه `feat/visual-studio-persistence`، Migration سفارشی `0011_visual_projects` و API مالکانه `/api/projects/[id]/visual` را اضافه می‌کند. ایجاد تنها برای پروژه فاقد کد تولیدشده است؛ سند با نسخه مورد انتظار ذخیره می‌شود و ذخیره هم‌زمان قدیمی پاسخ ۴۰۹ می‌گیرد. بدنه درخواست به ۵۱۲ کیلوبایت محدود است. سه قالب داده نمونه، انتخاب صفحه، ویرایش متن، Undo/Redo، حالت دستگاه و دریافت فایل `App.tsx` از آخرین نسخه ذخیره‌شده افزوده شده‌اند. همه پیش‌نمایش‌ها داده‌محور و بدون تماس AI هستند؛ داده و دکمه‌های فرم نمونه‌اند.

خروجی فایل React قطعی و قابل بررسی است؛ هنوز به Template Renderer، ایجاد Generation جدید، GitHub یا APK وصل نیست. برای نسخه کامل، انتخاب و افزودن و جابه‌جایی صفحات/المان‌ها، تغییر رنگ و سایر خصوصیات، Asset مجاز، تست واقعی مرورگر و انتشار ایمن باقی‌اند. تغییرات هم‌زمان با ویرایش در برگهٔ دیگر باید با بارگذاری دوباره بررسی شود؛ ذخیره خودکار overwrite نمی‌کند.

برای Staging تنها پس از ایجاد دیتابیس ایزوله و بررسی journal، 0008 تا 0011 را اعمال کنید. ابزار custom Drizzle برای 0011 به دلیل timestamp قدیمی‌تر از journal موجود اصلاح شد؛ snapshot خودکارِ کپی‌شده از 0007 حذف شده چون Migrationهای قبلی سفارشی‌اند و تصویر نادرستی از schema می‌داد. پیش از استفاده از `db:generate` عادی، همگام‌سازی snapshotهای Drizzle نیاز به بررسی جداگانه دارد. rollback 0011 پس از بازگرداندن کد و بکاپ، حذف جدول `visual_projects` با Migration مدیریت‌شده است و همه پیش‌نویس‌ها را حذف می‌کند؛ در Production فقط با تأیید مالک.

## ادامه: مدیریت صفحه و المان

در شاخه تکمیلی، افزودن، تغییر نام، ترتیب و حذف صفحه با تأیید و افزودن، ترتیب و حذف المان‌های داده‌محور اضافه شده است. المان انتخاب‌شده در Canvas مشخص می‌شود و جهت RTL/LTR قابل انتخاب است. این ویرایش‌ها محلی هستند و تا ذخیره، Revision جدیدی ندارند. در آزمون مرورگر مستقل با داده ساختگی و اندازه ۳۹۰ و ۱۴۴۰، ایجاد قالب، ویرایش، Undo/Redo، افزودن صفحه، ذخیره و بارگذاری مجدد موفق بود و تماس AI رخ نداد. این تست حساب واقعی، پرداخت، مجوزهای Production یا اتصال Build را اثبات نمی‌کند.

تصویر در کتابخانه افزودن فعال نشده چون Asset دارای شناسه پایدار و کنترل مالکیت وجود ندارد؛ placeholder موجود به معنی تصویر عملیاتی نیست. ویرایشگر فعلی به ایجاد Generation و Build APK متصل نیست و فرم‌های سه قالب صرفاً داده نمونه‌اند. آماده‌سازی و انتشار Production همچنان به تعیین نرخ و بودجه معتبر، رسیدگی به مصرف نامشخص تاریخی و آزمایش Migrationهای 0008–0011 در محیط جداگانه نیاز دارد. محدودیت تعداد شاخه Neon مانع ساخت شاخه Staging شد؛ هیچ شاخه‌ای حذف نشده است.

### تنظیم تعرفه توسط مدیر

پس از آزمون و اجرای Migration `0012_panoramic_champions` در محیط مناسب، شناسه UUID حساب مدیر احراز هویت‌شده را در متغیر سروری `PRICING_ADMIN_USER_IDS` قرار دهید (چند شناسه با ویرگول جدا می‌شوند). لینک «مدیریت تعرفه هوش مصنوعی» فقط برای این حساب‌ها در تنظیمات نمایش داده می‌شود؛ API نیز همان کنترل را اعمال می‌کند. نرخ ورودی و خروجی برای شناسه دقیق هر مدل لیارا، به تومان برای یک میلیون توکن و با درنظرگرفتن بالاترین تعرفه بازه‌های مدل، توسط مدیر ثبت می‌شود. نرخ‌های ذخیره‌شده بر متغیر قدیمی `LIARA_MODEL_PRICING_JSON` اولویت دارند؛ نرخ هنگام رزرو برای تسویه همان درخواست ثابت می‌ماند. نرخ بیش از ۳۰ روزه معتبر نیست و باید تأیید مجدد شود. هیچ نرخ تومانی فرضی ثبت نمی‌شود: کاتالوگ عمومی دلار است و تعرفه حساب و نرخ تبدیل آن معلوم نیست. نمایش کاتالوگ فقط برای راهنمایی است. فعلاً ثبت تعرفه در این صفحه فقط برای Liara AI Gateway پشتیبانی می‌شود.

این قابلیت به‌تنهایی مجوز مصرف ایجاد نمی‌کند: سقف‌های `AI_TOMAN_LIMITS_JSON` و رسیدگی به مصرف قبلی بدون قیمت همچنان لازم‌اند. Migration باید ابتدا روی شاخه آزمایشی Neon و پیش از استقرار بررسی شود.
